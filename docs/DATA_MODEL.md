# Каноническая модель данных

## Почему сущности разделены

Факт, вывод, прогноз и намерение отвечают на разные вопросы. Их совместное хранение создаёт ложную историю и обучает систему на собственных предположениях. Поэтому ALMA хранит их раздельно.

| Смысл | Каноническая сущность | Участие в историческом evidence |
|---|---|---|
| Измерение или оценка состояния | `Observation` | Да, только measured/user-confirmed и canonical |
| Произошедшее действие или событие | `CanonicalEvent` | Да, при подтверждённом присутствии |
| Эпизод симптома | `SymptomEpisode` | Да, с presence semantics |
| Период контекста жизни | `ContextPeriod` | Да, как modifier/context |
| Будущее намерение | `PlannedEvent` | Нет, пока не подтверждено |
| Вычисленная динамика | `DynamicFeature` | Производное evidence с версией алгоритма |
| Персональная закономерность | `PersonalPattern` | Вывод, не исходный факт |
| Проверяемое ожидание | `ForecastRecord` | Нет; после окна получает outcome |
| Предложенное действие | `RecommendationRecord` | Нет; хранится отдельно от medical advice |
| Персональный инструмент | `PersonalToolRecord` | Результат повторной персональной проверки |
| Эксперимент | `PersonalExperimentRecord` | Отдельный план и результат |

## Общий envelope

Все записи наследуют `VersionedRecord`: стабильный `id`, `version`, `createdAt`, `updatedAt`, optional `userId`, `origin`, `deletedAt`. Изменение сохраняет identity; soft delete инвалидирует зависимую текущую модель.

Фактические записи дополнительно содержат локальную дату, timezone, точность времени, источник, confidence, schema version и epistemic status.

## Epistemic status

- `measured` — получено измерением или внешним источником;
- `user_confirmed` — подтверждено человеком;
- `inferred` — вычисленный вывод, не факт;
- `predicted` — прогноз;
- `planned` — намерение или будущее событие.

Core допускает в personal evidence только первые два статуса. Seed/demo/synthetic всегда исключаются.

## Presence

- `present` — известно, что явление было;
- `confirmed_absent` — человек или надёжный источник подтвердил отсутствие;
- `unknown` — данных недостаточно.

`unknown` никогда не превращается в `0` или `false`. Подтверждённое отсутствие может стать контрольным примером.

## Время и интервалы

`timePrecision` сохраняет различие между точным временем, приблизительным временем и записью только на дату. Интервалы имеют начало и необязательный конец. Приведение date-only записи к полудню используется только для вычислительного упорядочивания и не повышает точность исходного факта.

## История моделей

Baselines и patterns имеют `validFrom/validTo`. Материальное изменение baseline закрывает прежний период и создаёт новый. Исчезнувший pattern сохраняется с lifecycle `no_longer_observed`; прежние feed items остаются immutable, а изменение публикуется новой записью.
